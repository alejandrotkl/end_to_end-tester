# 🔗 Playwright Link Tester

Автоматическое **end-to-end тестирование списка ссылок** с помощью [Playwright](https://playwright.dev).  
Загружаете файл со ссылками — программа сама открывает каждую в браузере, проверяет её работоспособность и выводит подробный отчёт.

</div>

> [!IMPORTANT]
> Для работы требуется установленный **Node.js** (LTS-версия) и браузер **Chromium**, который ставится отдельной командой (см. раздел [Установка](#️-установка-и-запуск)).

> [!TIP]
> Весь вывод программы — консоль, лог-файл и сообщения об ошибках — на **русском языке**.

> [!NOTE]
> Проект работает одинаково на **Windows, macOS и Linux** — он написан на Node.js и Playwright, которые кросс-платформенны. Ниже приведены команды установки для каждой ОС.

## ℹ️Что делает программа

Для каждой ссылки из вашего файла программа:

1. Открывает страницу в headless-браузере (Chromium)
2. Проверяет, что получен ответ и **HTTP статус меньше 400**
3. Проверяет, что элемент `<body>` виден на странице
4. Проверяет, что заголовок страницы (`<title>`) не пустой
5. Замеряет **время загрузки** и **общее время обработки** ссылки
6. Записывает результат в консоль и текстовый лог

## ⚙️Установка и запуск

### 1. Установите Node.js (LTS), если он ещё не установлен

**Windows** (PowerShell):

```powershell
winget install OpenJS.NodeJS.LTS
```

**macOS** (через [Homebrew](https://brew.sh)):

```bash
brew install node
```

**Linux** (Debian/Ubuntu):

```bash
sudo apt update && sudo apt install -y nodejs npm
```

На других дистрибутивах используйте свой пакетный менеджер (`dnf`, `pacman` и т.д.) либо [официальный установщик](https://nodejs.org).

После установки перезапустите терминал и проверьте версию: `node -v` (нужна версия 18 или новее).

### 2. Установите зависимости проекта

Команда одинакова на всех ОС:

```bash
npm install
```

### 3. Установите браузер Chromium для Playwright

```bash
npx playwright install chromium
```

> [!IMPORTANT]
> **Только для Linux:** Chromium требует системные библиотеки, которых нет по умолчанию на многих дистрибутивах. Если при запуске тестов Playwright ругается на отсутствующие библиотеки (`libnss3`, `libatk` и т.п.), выполните:
>
> ```bash
> sudo npx playwright install-deps
> ```
>
> Либо сразу поставьте браузер вместе с зависимостями: `npx playwright install --with-deps chromium`.

### 4. Подготовьте файл со ссылками

См. раздел [Формат файла со ссылками](#-формат-файла-со-ссылками).

### 5. Запустите тесты, указав файл со ссылками

Команды одинаковы на всех ОС:

```bash
npm test -- --file links.txt
```

Либо запустите без аргумента — программа сама спросит путь к файлу:

```bash
npm test
```

> [!TIP]
> Полный путь указывать необязательно. Если файл не найден в текущей папке, программа автоматически поищет его по имени в папке проекта, на Рабочем столе, в Документах и Загрузках. Если найдётся несколько файлов с таким именем — будет предложено выбрать нужный из списка.

## 📄 Формат файла со ссылками

Поддерживаются два формата.

**Текстовый файл (`.txt`)** — одна ссылка на строку. Строки, начинающиеся с `#`, игнорируются:

```txt
# Мои ссылки для проверки
https://example.com
https://playwright.dev
```

**JSON-файл (`.json`)** — массив ссылок или объект с полем `links`:

```json
{
  "links": [
    "https://example.com",
    "https://playwright.dev"
  ]
}
```

> [!WARNING]
> Ссылка обязательно должна начинаться с `http://` или `https://`, иначе она будет проигнорирована.

## ℹ️Краткие описания файлов

- [**`src/run.ts`**](./src/run.ts) — точка входа. Спрашивает/принимает путь к файлу со ссылками (с поиском по имени, если путь не указан точно) и запускает Playwright
- [**`src/findFile.ts`**](./src/findFile.ts) — ищет файл по имени в папке проекта, на Рабочем столе, в Документах и Загрузках, если он не найден по прямому пути
- [**`src/loadLinks.ts`**](./src/loadLinks.ts) — читает и парсит ссылки из `.txt`/`.json` файла
- [**`src/linkReport.ts`**](./src/linkReport.ts) — ведёт лог по каждой ссылке (`test-results/links.log`)
- [**`src/globalSetup.ts`**](./src/globalSetup.ts) — выполняется один раз в начале прогона и создаёт файл лога
- [**`src/russianReporter.ts`**](./src/russianReporter.ts) — кастомный репортер Playwright: переводит служебный вывод на русский язык и печатает итоговую сводку по всем ссылкам
- [**`tests/links.spec.ts`**](./tests/links.spec.ts) — сами тесты: динамически создаются по одному на каждую ссылку из файла
- [**`playwright.config.ts`**](./playwright.config.ts) — конфигурация Playwright (таймауты, репортер, поведение при ошибках)

## 📊 Логи и результаты

Во время прогона в консоли построчно выводится результат по каждой ссылке:

```
[УСПЕХ] https://example.com | HTTP 200 | загрузка: 445 мс | всего: 481 мс
[ОШИБКА] https://broken-site.com | HTTP нет ответа | загрузка: 0 мс | всего: 2144 мс | ...

--- Итоги ---
Всего: 2 | Успешно: 1 | Ошибок: 1
Среднее время загрузки: 223 мс | Среднее общее время: 1313 мс
Файл лога: test-results/links.log
```

Полный лог сохраняется в файл:

```
test-results/links.log
```

> [!NOTE]
> На Windows путь в выводе будет отображаться с обратным слешем (`test-results\links.log`) — это не ошибка, а стандартное поведение Node.js на этой ОС.

При падении теста Playwright также сохраняет скриншот страницы в папку `test-results` — его можно открыть напрямую, без сервера.
